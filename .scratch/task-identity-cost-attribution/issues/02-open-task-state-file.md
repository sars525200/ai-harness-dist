## Question

D3 要「未結案任務落 JSON，新室開場 hook 回餵」；D4 要「改名走 rename 不是重新宣告」。
**這份狀態檔長什麼樣、誰寫、併發怎麼辦？**

要定的五件事：

1. **檔案落點與粒度**：一個全域檔還是一個任務一個檔？放 `D:\.ai-harness\state\`
   （既有 event log／便箋都在那）還是別處？
2. **誰寫**：hook 自己寫（UserPromptSubmit／Stop），還是模型透過某個動作寫？
   hook 寫的好處是不靠模型記得；壞處是 hook 判斷不了「這是新任務還是同一個」。
3. **多 session 併發**：這台機器常態 2–3 個 session 並行，各自有不同任務。
   狀態檔是 per-session 還是全域？全域的話「目前任務」對誰而言？
   ⚠ 已知這個 repo 多 session 併行，狀態檔若進版控會被掃進別人的 commit。（2026-08-27 訂正：原寫「外部程序定期 `git add -A`」，實查查無實據；危害不變，污染者是併行的另一個 session。）
4. **結案動作**：什麼算結案？user 明說？收工時？還是逾時自動結？
   不結案會一直回餵舊任務名 —— 那比沒有更糟（新工作被記到舊任務頭上）。
5. **rename 的形狀**：改名要改哪一筆、歷史歸因要不要跟著改（改了統計會回溯變動，
   不改則同一個任務在圖上有兩個名字）。

回餵機制與結案語意會決定歸因資料層的 key 空間，03 動不了之前必須先答。
