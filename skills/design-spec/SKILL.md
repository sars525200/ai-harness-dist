# Design 階段執行器（/design-spec）

> 本 skill 是全域 `CLAUDE.md` §3 Design 節與 `D:\.ai-harness\WORKFLOW_5STAGE_PLAN.md`
> §7（規模判準）／§8（交付物格式）的**步驟執行器**——規則本體在那兩處，不一致時以那兩處為準。
> 核心：**Design 的交付物是「別人能接手的規格」，不是「我心裡有數」。**
>
> 為什麼要有這一支、以及它為什麼在共用層（換部門還成立）→ `WORKFLOW_5STAGE_PLAN.md`
> 的「Review 有 7 支、Design 有 0 支」觀察與 W-10。

## 步驟

### 1. 判規模（決定要不要走完這支）

用 §7 判準。**每條都是動工前可答的事實**，不含「複雜不複雜」——要判斷的判準會被自我豁免：

- **M**＝資料遷移／DELETE・動角色·規則·hook・跨 repo・user 說「計畫書／大型」・預估跨 session
- **S**＝改 **≥3 檔**・碰硬規則區・改有多處副本的共用邏輯・要部署・要派 subagent
- **L**＝以上都不命中

**完成判準**：級別已在自我宣告裡講出來。**L／S 到這裡就結束**——它們不落檔，
交付物留在對話（欄位仍要齊全）。**明確 M 級改開 wayfinder map（見邊界），也不走這支**；
繼續往下的是「規模待定／人要正式計畫書／疊代既有 `*_PLAN.md`」這三種。

### 2. 落檔位置：疊代既有，新建要有理由

先掃既有計畫書（`grep -l` 關鍵字掃 `*_PLAN.md`），**疊代那一份**——
多一份計畫書就多一個會過期、要清理、沒人讀的東西。
新建的唯一正當理由是「這個主題在既有計畫書裡沒有歸屬」，而且要說得出是哪個主題。

**完成判準**：講出落在哪一份檔的哪一節，或說出新建的理由。**不准兩份都寫。**

### 3. 列待決分岔並逐項問完

分岔表四欄：**# ｜分岔｜選項｜傾向（附理由）**。然後用選擇題逐項問
（一次最多 4 題、第一個選項標「(推薦)」並附理由）：

- **Claude Code** → `AskUserQuestion`
- **Cursor** → `AskQuestion`（Questions 面板）。掃 MCP namespace 找不到不算沒有。
- 兩種都掃不到 → **停下來講工具缺失**，禁止改寫成聊天列選項或自製 HTML。

- **禁用陳述句把決定丟回去**（「兩件事留給你決定：…」句號結尾）——那正是 AWC-1 在擋的形狀。
- **自己能查證的不要問**：事實查證後直接做。問題留給「不同讀法會導致材料上不同的工作」。
- **討論中長出來的新分岔要補進表裡**，不要私下決定。2026-08-06 實例：W-6（角色數量）
  是設計到一半才發現的——因為「不給 Bash」之後兩個角色能力變得完全相同。

**完成判準**：分岔表每一列都有 user 的決定，且**決定已寫回計畫書**（不是只留在對話裡）。

### 4. 驗證方式守門（沒寫完不得進 Execute）

**動工前就要寫好怎麼驗**，逐項列「驗什麼｜怎麼驗」。判準比「要驗什麼」高一階：

- 每一項要答得出**「怎麼證明它會紅」**——新寫的驗證預設它自己有問題。
- **兩支自己寫的實作互相比對不算獨立驗證**：共享同一個誤解時會一起錯。
  2026-08-06 實測踩過：原訂「產生器 vs 探測腳本兩支比對」，做到一半發現兩支都是我寫的，
  V1 當場降級成單元測試＋變異證明。**寫規格時就該看出來的事，不要留到執行時。**
- 驗不到的（需重啟／要真機／等排程／被閘門擋下）**當下就寫進 `PENDING_VERIFY.md`**，
  四欄齊全：項目｜為何沒驗｜驗證指令逐字｜誰跑。

**完成判準**：驗證節非空，且每一項都寫得出「會紅的條件」。
**空白＝沒有驗證計畫，不是「等做完再說」。**

### 5. 標「待審核」，把後續交給 PR-1（**落檔的那一份才有**）

步驟 1–4 全部完成的那一刻——分岔表每列都有 user 的決定、驗證方式每項都答得出
「怎麼證明它會紅」——在計畫書檔頭加一行：

```
> 狀態：待審核
```

**這一行是 PR-1 的握手暗號**：之後只要這輪動過這份檔，Stop hook 沒看到 hash 對得上的
`ADVERSARIAL_REVIEW_PASSED` marker 就擋下對話結束——不靠誰記得問。機制本體見 `STOP_HOOK_MARKER_PLAN.md`（絕對路徑 `D:\.ai-harness\STOP_HOOK_MARKER_PLAN.md`）。

四件事講清楚：

- **時機是「寫完要送審」，不是「建檔就標」**。建檔就標會讓寫計畫書的每一輪 Stop
  都被擋住，那是 D5 的 WARN 疲勞重演。
- **只標落檔的那一份**。L／S 不落檔，沒有東西可標——判準沿用步驟 1，不另開一套。
- **舊計畫書不回頭補標**。沒標記＝放行是 B1 的刻意設計（機制被動、由人決定何時送審）；
  回頭補標等於一次把幾十份檔推進審查佇列。
- 真的不值得審一輪時（只改錯字、只更新狀態欄），用逃生口而不是把標記拿掉：
  `<!-- ADVERSARIAL_REVIEW_SKIP sha256=<hash>: <理由> -->`。它綁 hash（內容一改就失效）且留痕計次。
  ⚠ **重簽的判準是「差異在不在原本略過的範圍內」，不是「hash 對不上就重算」**——後者是偽造憑證的唯一動作。
  純狀態／進度區塊可以包在 `REVIEW_SCOPE_IGNORE_START/END` 之間，改它不會讓 marker 失效。

**完成判準**：落檔的計畫書檔頭有 `> 狀態：待審核`，或說得出為什麼這份不必標
（例如它是 L／S 不落檔、或它是既有舊檔只做局部疊代）。

## 邊界

- **只產出規格，不寫實作**。不改程式、不改設定、不部署——那是 Execute 的事。
- **分岔沒有 user 的決定就不進 Execute**——選項與傾向擺出來就停，不替人決定。
- **明確 M 級的規劃層改走 `/wayfinder` map，不是這支**；規模待定才用這支（安全預設）。L 級單點不用。

## 交出什麼

計畫書五節齊全（現況 → 目標 → 做法 → 驗證 → 狀態）＋ 分岔表全部有決定。
下一棒（Execute）要能**不必再問「這樣對嗎」**就開始——那是 §8 交接契約對 Design 的要求。

走完步驟 5 之後，`/adversarial-review` 由 PR-1 擋著要，不必靠記得問。
**S 級碰 [DB｜邏輯] 類高風險設計時仍要主動問**——它們不落檔、標不了記，機制接不到，
那一格還是靠人（判準是「錯誤成本高不高」不是「複雜不複雜」）。
