# 平台能力偵測（/skill-watch）

> **這支存在的理由**：2026-08-22 實測 —— `SkillViewer` 那份平台技能清單停在 **7/28**，
> 而平台在那之後把 `/review` 改名成 `/code-review`、新增了 `design` 與 `artifact-diagramming`。
> 拿那份清單做決定的人，會被指去用一支**已經改名的指令**和一支**不存在的技能**。
> 更值得記的是：官方早就內建了 `/deep-research`（多角度 fan out ＋ 交叉驗證 ＋ 逐條投票），
> 而我們正打算自己包一支功能更弱的來用——**沒有人在看平台加了什麼**。

## 這支不做什麼

- **不自動套用**。上游更新的安全套用路徑不存在（`npx skills update` 會靜默覆寫本地修改，
  還把資料夾掉包成 junction 讓 skill 檔離開版控）。所以只提報，裝不裝是人的決定。
- **不下「可合併／可取代」的判定**。它只把候選端到你面前：多了什麼、少了什麼、
  名稱或描述與現有哪幾支重疊。判斷留給人。
- **不改任何 skill 檔**。

## 步驟

### 0. 先確認要查哪些平台

```
py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms
```

（一律走 `run.py`，理由見步驟 1 的 symlink 說明。）

它會印「要查的平台」與「定義裡有、你還沒勾」。**兩件事要照做**：

1. **有沒勾的就用選擇題問 user 這次要不要勾**（全域 `CLAUDE.md`：問題一律用選擇題）。
   不要自己替他決定——「要監控哪些平台」是他的事，這支 skill 存在的理由就是這個。
2. **要改就走旗標，不要自己用 Edit 改那個 JSON**：

   ```
   py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms --enable <平台 id>
   py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms --disable <平台 id>
   ```

   理由：寫回要保留使用者手加的其他鍵與其他平台的開關，而那份保留邏輯有測試守著
   （`tests/test_skill_watch_platforms.py`，含三種寫壞的變異證明）。用 Edit 改就繞過了它。

**一個平台都沒勾的話不必你記得——`run.py` 會自己拒跑**（票 19 · 2026-08-24）：
exit 2、**不呼叫擷取器**（省下那 0.6 USD）、而且**不前進 `lastSuccessAt`**。
最後那一項是重點：看板那格（`_p_skill_watch_alive`）只讀 `lastSuccessAt`，
「什麼都沒查」被記成「成功檢查過」會讓它**永遠綠**，而全部停用正是最需要它變紅的時候。
勾了一個**沒有擷取實作**的平台（今天只有 `claude-code` 有）也一樣拒跑——
不讓它「跑起來但其實只查了 Claude Code」。

⚠ 在票 19 之前，這裡寫的是「一個都沒勾就不要往下跑」，而**守的人是模型不是程式**：
直接打 `py -3 run.py` 就繞過去了。這句話現在有測試綁著
（`tests/test_skill_watch_run.py` 的 `test_toggle_gate_*` 與 `test_skillmd_documents_toggle_gate`），
改程式不改這裡、或改這裡不改程式，都會紅。

### 1. 跑偵測

```
py -3 "${CLAUDE_SKILL_DIR}/run.py"
```

⚠ **一定要走 `run.py`，不要自己拼路徑跳出 skill 目錄**。
`~/.claude/skills` 是指向 `<harness>/skills` 的 symlink，而 `${CLAUDE_SKILL_DIR}`
展開的是 **symlink 那一側**；寫 `${CLAUDE_SKILL_DIR}/../../tools/…` 會被解析成
`~/.claude/tools/`（不存在）。`run.py` 用 `Path(__file__).resolve()` 跟隨 symlink
自己找到 harness 根，兩側呼叫都對。

**預設就是要落檔的那一次**：更新基準、有變動寫進 `TODOS.md`。
只想看一眼不留痕跡就加 `--dry-run`。

⚠ **這支不掛排程、不接收工流程**（2026-08-23 user 定：收工的步驟已經太多，
不再往 `/shougong` 疊東西）。它靠你想到的時候打 `/skill-watch`——
所以**每次跑完都要講基準日期**，讓人自己看得出「上次檢查是多久以前」。

exit code：**0＝跑成功**（不論有無變動）、**2＝失敗**。失敗一律拒跑不猜，
訊息會指名缺什麼（設定檔壞掉／擷取結果不可信／中性目錄前提失效）。

### 2. 讀懂它印的東西

| 那一行 | 意思 | 要注意什麼 |
|---|---|---|
| `抓到 N 支，濾掉本機自建 M 支 → 平台內建 K 支` | 注入清單裡屬於平台的部分 | **M 突然變了**代表本機自建 skill 有增減，或擷取環境變了 |
| `官方有、本機沒有的 Skill：N 支 → …` | 官方文件列了但這台拿不到 | **常態不是變動**（無頭沒有 Artifact 工具那類）⇒ **不要進對照表** |
| `⚠ 官方新增、本機沒有的：N 支` ＋ 逐項 `· 名稱 — 一句說明` | 上次沒有、這次才出現 | **這是「平台推出新東西」的訊號**，會寫進 TODOS。那句說明**直接抄進對照表**，不要重寫 |
| `消失 N 支` | 基準有、現在沒有 | 若同時有「新增」且名稱相近，看「改名候選」那幾行 |

⚠ **改名候選只是提示不是判定**（相似度 ≥0.6 就列）。`review`→`code-review` 是 0.706，
但 `ui-rules`↔`verify-rules` 也有 0.700。**逐條自己看**。

### 3. 回報給 user —— **一句結論 ＋ 一張對照表**

**第一行就是結論，不要鋪陳。**

- 無變動：`✅ 平台能力無變動（基準 08-22 22:39，1 天前）`
- 有變動：`⚠ 平台有 3 筆變動，其中 1 筆可能取代你現有的技能`

然後**一張表，只列變動**，四欄固定：

| 變動 | 能力 | 官方說明 | 用途／與誰重疊 |
|---|---|---|---|
| 🆕 | `/dataviz` | Design guidance for charts, graphs, and dashboards. | 畫圖表・**無重疊** |
| ✏ 改名? | `/review` → `/code-review` | Review the current diff… | 相似度 0.71・逐條自己看 |
| ❌ 消失 | `/deep-research` | — | ☠ 你自建的 `/research` 就是代替它的 |

**每一欄怎麼填**：

| 欄 | 來源 | 注意 |
|---|---|---|
| 變動 | 工具印的 | 只有 🆕／✏ 改名?／❌ 消失 三種 |
| 能力 | 工具印的 | 帶斜線寫成 `/name`，人才知道怎麼打 |
| 官方說明 | **工具已經壓成一句印出來了**，直接抄 | 不要自己去 WebFetch 重寫，也不要憑印象 |
| 用途／與誰重疊 | **這一欄要你動腦** | 去 `<harness>/SkillViewer/platform_skills.json` 的 `skills[]` 找名稱或用途相近的**自建**技能（`origin` 是 `global`／`project` 那些） |

**四條規則**：

1. **不要貼整份清單**，只列差異。
2. **「官方有、本機沒有」那批不要進表**——那多半是 headless／interactive 的系統性
   差異（無頭沒有 Artifact 工具），是**常態不是變動**。要提就一行帶過。
3. **「用途／與誰重疊」說不出來就寫「無重疊」，不要留空**——空欄會被讀成「還沒查」。
4. **不下判定**。表是把候選端到人面前，「要不要換掉自建的那支」是他的決定。

登記簿（`TODOS.md`「全域·需求」表）已經自動寫了，看板會收。
**但你還是要在對話裡講一次**——登記簿是給未來的人看的，當下這個人需要現在就知道。

### 3.5 這兩塊**無論有沒有變動都要帶**（2026-08-24 補）

工具每次都印，而回報規格原本一個字都沒要求 ⇒ **模型照規格寫回報時就把它們丟掉了**。
母計畫書 §18.7 ⑥ 記著「報告改版：Workflow 不再隱形」——那次**只做到工具那一半**。

**① Workflow 現況**：工具印的 `[Workflow] 名稱 — 說明` 逐項帶進回報。
理由就是這支的開場白：`/deep-research` 從來沒被端到人面前過，而我們差點自己包一支更弱的。
Workflow **不進注入清單、也不進基準**（「有沒有」比不出來）⇒
**除了每次講一次，沒有任何機制會讓人看見它。**

**② 「官方有、本機沒有」那批的可用／可剃除判斷**：一支一行，三欄——
`官方能力｜官方說明（工具抓的·直接抄）｜與哪支自建重疊，或「無重疊」`。
自建清單去 `<harness>/SkillViewer/platform_skills.json` 的 `skills[]` 撈
`origin` 是 `global`／`project` 的那些（撈得到 `description`，不必另外查）。

⚠ **與步驟 4「不要端出來」不衝突，差別要看清楚**：
**禁止**的是把它們**當成變動**（進變動表、進 `TODOS.md`、講成「平台新增了 N 支」）；
**要求**的是把它們**當成現況參考**列出來，並明說「這批是無頭與互動環境的系統性差異，
不是平台變動」。**兩句都對——原本只寫了前半，所以不完整。**

⚠ **仍然不下判定**：重疊分析是把候選端到人面前，換不換是他的決定（見「這支不做什麼」）。

⚠ 這一節有測試綁著（`tests/test_skill_watch_run.py` 的
`test_skillmd_report_spec_covers_what_the_tool_prints`）：判準取自**工具原始碼實際會印的字串**，
所以工具改了輸出而這裡沒跟、或這裡被刪掉，**兩個方向都會紅**。
⚠ 但它**綁不到「模型有沒有真的照做」**——那是模型產的字不是程式輸出，測試看不到，只能靠人看。

### 4. 沒變動時

**一行講完，帶基準日期與距今多久**：

```
✅ 平台能力無變動（基準 2026-08-22 22:39，1 天前）
```

**不要沉默**——「沒說話」與「沒跑成功」在使用者眼裡長得一樣，而這支存在的理由
正是要消除這種歧義。**不要把「官方有、本機沒有」那批講成變動**——
但**要照 §3.5 帶上它們的可用／可剃除判斷與 Workflow 現況**，那兩塊無論有沒有變動都要帶。
（原本這裡寫「不要端出來」，2026-08-24 訂正：不該端的是「當成變動」，不是「不准提」。）

## 完成判準

- 指令跑過且 exit 0 或 2（2 要把失敗原因講出來，**不可當成「沒變動」**）
- **第一行就是結論**（`✅ 無變動…` 或 `⚠ 有 N 筆變動…`），不是鋪陳
- 有變動 → **對照表四欄齊全**，且「用途／與誰重疊」**沒有空欄**（說不出就寫「無重疊」）
- 有變動 → `TODOS.md` 已有對應那一列
- 無變動 → 已明說，帶基準日期**與距今多久**
- **沒有把「官方有、本機沒有」那批當成變動端出來**
- **回報帶了 Workflow 現況**（工具印幾支就講幾支；一支都沒有也要說「本次 0 支」）
- **「官方有、本機沒有」那批有 §3.5 的三欄判斷**，且「與哪支自建重疊」**沒有空欄**（說不出就寫「無重疊」）

## 換一個部門要改什麼

- **路徑自己解析**：`run.py` 從自身位置往上三層找 harness 根（`Path(__file__).resolve()`），
  沒有寫死任何絕對路徑，也不受 symlink／junction 影響。
- **設定從 `harness.config.json` 讀**：腳本自己會讀 `currentProject`，讀不到會拒跑並說缺什麼。
- **基準檔** 目前落在 `<harness>/SkillViewer/platform_skills.json`。
  ⚠ **缺基準時它是拒跑（exit 2），不是「自己建一份」**——訊息會說
  「這是『還沒建立基準』，不是『什麼都沒變』——先跑 `--capture`」。
  這是刻意的：回傳空表會讓「還沒建立基準」偽裝成「什麼都沒變」。
  （這裡原本寫「第一次跑會自己建立基準」，那句從來沒成立過，2026-08-23 票 16 修正。
  真正的 bootstrap 由票 14 做，屆時要回頭改這一段；**在那之前不要預寫未來式**。）

⚠ **要監控哪些平台已經可以設定了**（2026-08-23 票 08）：定義在
`<harness>/skills/skill-watch/platforms.json`（進版控·跟著 skill 走），
開關在 `<harness>/state/skill_watch_platforms.json`（本機狀態·不進版控）。
**缺開關檔＝全關**，什麼都不會查；用步驟 0 的旗標勾選。

**目前定義裡只有 Claude Code**。加第二個平台除了在定義檔加一筆，還要有對應的
adapter 實作（票 09）——`platforms.json` 裡放一個沒有 adapter 的平台，等於埋一個
勾了就爆的選項。
⚠ `UNIVERSAL_HARNESS_PLAN.md` §5「在有第二個實際要用的工具之前不預先抽象」
**這條的擋箭牌已經解除**（2026-08-23 票 01：Cursor 確認為第二個實際要用的工具，
`probe = injected-list`），W-12 因此定案介面一次到位。

設計、對抗式覆核紀錄與決策票見 `<harness>/SKILL_WATCH_PLAN.md`
（§14 規格／§15·§16 覆核／§17 決策票待辦）與
`d:\IT-department\.scratch\skill-watch-multiplatform\`。
