# 平台能力偵測（/skill-watch）

只提報、不自動套用、不改任何 skill 檔。裝不裝由人決定。
為什麼要這支、踩雷與決策票見 `SKILL_WATCH_PLAN.md`。

## 這支不做什麼

- **不自動套用**。`npx skills update` 會靜默覆寫，還把資料夾掉包成 junction 讓檔離開版控。
- **不下「可合併／可取代」的判定**。只把候選端到人面前。
- **不改任何 skill 檔**。

## 步驟

### 0. 先確認要查哪些平台

```
py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms
```

一律走 `skills/skill-watch/run.py`（步驟 1）。它會印「要查的平台」與「定義裡有、你還沒勾」。

1. **有沒勾的就用選擇題問 user 這次要不要勾**。不要自己替他決定。
2. **要改就走旗標，不要自己用 Edit 改那個 JSON**：

   ```
   py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms --enable <平台 id>
   py -3 "${CLAUDE_SKILL_DIR}/run.py" --platforms --disable <平台 id>
   ```

   寫回要保留其他鍵；邏輯有 `tests/test_skill_watch_platforms.py` 守著。

**一個平台都沒勾**時 `skills/skill-watch/run.py` 會自己拒跑：exit 2、不呼叫擷取器、**不前進 lastSuccessAt**。
看板 `_p_skill_watch_alive` 只讀 lastSuccessAt，「什麼都沒查」被記成成功會永遠綠。
勾了沒有擷取實作的平台也一樣拒跑。

### 1. 跑偵測

```
py -3 "${CLAUDE_SKILL_DIR}/run.py"
```

⚠ **一定要走 `skills/skill-watch/run.py`**。`~/.claude/skills` 是指向 harness 的 symlink，
`${CLAUDE_SKILL_DIR}` 展開在 symlink 側；自己拼 `../../tools/` 會走到不存在的
`~/.claude/tools/`。`skills/skill-watch/run.py` 用 `Path(__file__).resolve()` 跟隨 symlink。

預設會更新基準、有變動寫進 `TODOS.md`。只看一眼加 `--dry-run`。
不掛排程、不接收工。每次跑完都要講基準日期。

exit：**0＝跑成功**（不論有無變動）、**2＝失敗**。失敗拒跑不猜。

### 2. 讀懂它印的東西

| 那一行 | 意思 | 要注意什麼 |
|---|---|---|
| `抓到 N 支，濾掉本機自建 M 支 → 平台內建 K 支` | 注入清單裡屬於平台的部分 | **M 突然變了**＝本機自建有增減，或擷取環境變了 |
| `官方有、本機沒有的 Skill：N 支 → …` | 官方文件列了但這台拿不到 | **常態不是變動** ⇒ **不要進對照表** |
| `⚠ 官方新增、本機沒有的：N 支` ＋ 逐項 `· 名稱 — 一句說明` | 上次沒有、這次才出現 | **這是「平台推出新東西」的訊號**。說明**直接抄進對照表** |
| `消失 N 支` | 基準有、現在沒有 | 若同時有「新增」且名稱相近，看「改名候選」 |

⚠ **改名候選只是提示不是判定**（相似度 ≥0.6 就列）。`review`→`code-review` 是 0.706，
`ui-rules`↔`verify-rules` 也有 0.700。**逐條自己看**。

### 3. 回報給 user —— **一句結論 ＋ 一張對照表**

**第一行就是結論，不要鋪陳。**

- 無變動：`✅ 平台能力無變動（基準 08-22 22:39，1 天前）`
- 有變動：`⚠ 平台有 3 筆變動，其中 1 筆可能取代你現有的技能`

然後**一張表，只列變動**，四欄固定：

| 變動 | 能力 | 官方說明 | 用途／與誰重疊 |
|---|---|---|---|
| 🆕 | `/dataviz` | Design guidance for charts, graphs, and dashboards. | 畫圖表・**無重疊** |
| ✏ 改名? | `/review` → `/code-review` | Review the current diff… | 相似度 0.71・逐條自己看 |
| ❌ 消失 | `/deep-research` | — | ☠ 你自建的 `/research` 就是代替它的 |

| 欄 | 來源 | 注意 |
|---|---|---|
| 變動 | 工具印的 | 只有 🆕／✏ 改名?／❌ 消失 三種 |
| 能力 | 工具印的 | 帶斜線寫成 `/name` |
| 官方說明 | **工具已經壓成一句印出來了**，直接抄 | 不要 WebFetch 重寫 |
| 用途／與誰重疊 | **這一欄要你動腦** | 去 `<harness>/SkillViewer/platform_skills.json` 的 `skills[]` 找相近的自建（`origin` 是 `global`／`project`） |

1. **不要貼整份清單**，只列差異。
2. **「官方有、本機沒有」那批不要進表**——那是常態不是變動。要提就一行帶過。
3. **「用途／與誰重疊」說不出來就寫「無重疊」，不要留空**。
4. **不下判定**。「要不要換掉自建的那支」是人的決定。

登記簿（`TODOS.md`「全域·需求」表）已經自動寫了，看板會收。
**對話裡還是要講一次。**

### 3.5 技能盤點：**三段，順序固定**

無論有沒有變動都要帶。後兩段沒有第一段當分母就讀不懂。

**資料一次撈完**：`<harness>/SkillViewer/platform_skills.json` 的 `skills[]`，
每筆有 `name`／`description`／`origin`／`kind`。
`origin`＝`global`／`project` 是自建，`platform` 是官方。
⚠ **不要 WebFetch 重寫說明**，也**不要**從工具 stdout 抄官方說明——
`officialCrossCheck.missingLocally` **只存名稱**（`skill_watch_run.py:529` 印的就是純名單），
說明在 `skills[]` 裡。

#### ① 我有什麼

自建全部列出，**分「全域」與「專案」兩張表**，兩欄：`Skill｜用途`。
用途壓成一行（取 `description` 第一句）。

#### ② 我的哪些可以直接改用官方的

四欄：`自建｜可能取代它的官方｜本機拿得到？｜判斷`。
**一支都換不掉時就明講「一支都不能換」並給共同理由**。

#### ③ 官方有我沒有的 → 建議

三欄：`官方能力｜它做什麼｜建議`。用不到的寫「不需要，＜理由＞」。
**`[Workflow]` 類也放這一段**，不要另開一節。

⚠⚠ **這一段的標題絕對不能寫成「本機沒有」。**
工具量的是「**不在注入清單**」，而注入清單**只裝 skill**：內建 slash command 不會進去。
這條訊號到目前為止一次真缺口都沒抓到過（歷史命中率 0/6）。

1. 標題寫「**官方文件有、不在注入清單**」，**不要**寫「本機沒有」。
2. **預設當成「拿得到」**，要講缺口**必須先證明**：查 `claude --help` 的 `Commands:` 區，或請 user 打一個 `/` 看補完清單。
3. 證不出來的標「**未確證**」。不要因為它出現在這張表上就當成缺口。
4. 真正有價值的是 `⚠ 官方文件新增 N 項`——「官方出了新東西」是真訊號，「你缺了東西」不是。

⚠ 仍然不下判定。這一節有測試綁著
（`tests/test_skill_watch_run.py` 的 `test_skillmd_report_spec_covers_what_the_tool_prints`）。

### 4. 沒變動時

**一行講完，帶基準日期與距今多久**：

```
✅ 平台能力無變動（基準 2026-08-22 22:39，1 天前）
```

**不要沉默**。不要把「官方有、本機沒有」那批講成變動，
但**要照 §3.5 帶上它們的可用判斷與 Workflow 現況**。

## 完成判準

- 指令跑過且 exit 0 或 2（2 要把失敗原因講出來，**不可當成「沒變動」**）
- **第一行就是結論**（`✅ 無變動…` 或 `⚠ 有 N 筆變動…`）
- 有變動 → **對照表四欄齊全**，且「用途／與誰重疊」**沒有空欄**
- 有變動 → `TODOS.md` 已有對應那一列
- 無變動 → 已明說，帶基準日期**與距今多久**
- **沒有把「官方有、本機沒有」那批當成變動端出來**
- **回報帶了 Workflow 現況**（工具印幾支就講幾支；一支都沒有也要說「本次 0 支」）
- **「官方有、本機沒有」那批有 §3.5 的三欄判斷**，且「與哪支自建重疊」**沒有空欄**

## 換一個部門要改什麼

- **路徑自己解析**：`skills/skill-watch/run.py` 從自身位置往上三層找 harness 根，沒有寫死絕對路徑。
- **設定從 `harness.config.json` 讀**：讀不到會拒跑並說缺什麼。
- **基準檔**在 `<harness>/SkillViewer/platform_skills.json`。
  ⚠ **缺基準時它是拒跑（exit 2），不是「自己建一份」**——訊息會說
  「這是『還沒建立基準』，不是『什麼都沒變』——先跑 `--capture`」。
  回傳空表會讓「還沒建立基準」偽裝成「什麼都沒變」。

要監控哪些平台：定義在 `<harness>/skills/skill-watch/platforms.json`（進版控），
開關在 `<harness>/state/skill_watch_platforms.json`（本機、不進版控）。
**缺開關檔＝全關**。用步驟 0 的旗標勾選。

**目前定義裡只有 Claude Code**。加第二個平台還要有 adapter 實作——
`skills/skill-watch/platforms.json` 裡放一個沒有 adapter 的平台，等於埋一個勾了就爆的選項。
