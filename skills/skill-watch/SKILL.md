# 平台能力偵測（/skill-watch）

> **這支存在的理由**：2026-08-22 實測 —— `SkillViewer` 那份平台技能清單停在 **7/28**，
> 而平台在那之後把 `/review` 改名成 `/code-review`、新增了 `design` 與 `artifact-diagramming`。
> 拿那份清單做決定的人，會被指去用一支**已經改名的指令**和一支**不存在的技能**。
> 更值得記的是：官方早就內建了 `/deep-research`（多角度 fan out ＋ 交叉驗證 ＋ 逐條投票），
> 而我們正打算自己包一支功能更弱的來用——**沒有人在看平台加了什麼**。

## 這支不做什麼

- **不自動套用**。上游更新的安全套用路徑不存在（`npx skills update` 會靜默覆寫本地修改，
  還把資料夾掉包成 junction 讓 skill 檔離開版控）。所以只提報，裝不裝是人的決定。
- **不下「可合併／可取代」的判定**。它只把候選端到你面前：多了什麼、少了什麼、
  名稱或描述與現有哪幾支重疊。判斷留給人。
- **不改任何 skill 檔**。

## 步驟

### 1. 跑偵測

```
py -3 "${CLAUDE_SKILL_DIR}/run.py"
```

⚠ **一定要走 `run.py`，不要自己拼路徑跳出 skill 目錄**。
`~/.claude/skills` 是指向 `<harness>/skills` 的 symlink，而 `${CLAUDE_SKILL_DIR}`
展開的是 **symlink 那一側**；寫 `${CLAUDE_SKILL_DIR}/../../tools/…` 會被解析成
`~/.claude/tools/`（不存在）。`run.py` 用 `Path(__file__).resolve()` 跟隨 symlink
自己找到 harness 根，兩側呼叫都對。

**預設就是要落檔的那一次**：更新基準、有變動寫進 `TODOS.md`。
只想看一眼不留痕跡就加 `--dry-run`。

⚠ **這支不掛排程、不接收工流程**（2026-08-23 user 定：收工的步驟已經太多，
不再往 `/shougong` 疊東西）。它靠你想到的時候打 `/skill-watch`——
所以**每次跑完都要講基準日期**，讓人自己看得出「上次檢查是多久以前」。

exit code：**0＝跑成功**（不論有無變動）、**2＝失敗**。失敗一律拒跑不猜，
訊息會指名缺什麼（設定檔壞掉／擷取結果不可信／中性目錄前提失效）。

### 2. 讀懂它印的東西

| 那一行 | 意思 | 要注意什麼 |
|---|---|---|
| `抓到 N 支，濾掉本機自建 M 支 → 平台內建 K 支` | 注入清單裡屬於平台的部分 | **M 突然變了**代表本機自建 skill 有增減，或擷取環境變了 |
| `官方有、本機沒有的 Skill：N 支` | 官方文件列了但這台拿不到 | 通常是**版本還沒到**——想用就得升版 |
| `⚠ 官方新增而本機沒有` | 上次沒有、這次才出現 | **這是「平台推出新東西」的訊號**，會寫進 TODOS |
| `消失 N 支` | 基準有、現在沒有 | 若同時有「新增」且名稱相近，看「改名候選」那幾行 |

⚠ **改名候選只是提示不是判定**（相似度 ≥0.6 就列）。`review`→`code-review` 是 0.706，
但 `ui-rules`↔`verify-rules` 也有 0.700。**逐條自己看**。

### 3. 回報給 user

有變動時已自動寫進登記簿（`TODOS.md`「全域·需求」表），看板會自己收進去。
**你還是要在對話裡講一次**——登記簿是給未來的人看的，當下這個人需要現在就知道。

講三件事：**多了什麼／少了什麼／需不需要升版才拿得到**。
不要把整份清單貼出來，只講差異。

### 4. 沒變動時

明說「平台能力無變動」並帶上比對基準的日期。**不要沉默**——
「沒說話」與「沒跑成功」在使用者眼裡長得一樣，而這支存在的理由正是要消除這種歧義。

## 完成判準

- 指令跑過且 exit 0 或 2（2 要把失敗原因講出來，不可當成「沒變動」）
- 有變動 → 差異已在對話裡講清楚，且 `TODOS.md` 已有對應那一列
- 無變動 → 已明說，並帶基準日期

## 換一個部門要改什麼

- **路徑自己解析**：`run.py` 從自身位置往上三層找 harness 根（`Path(__file__).resolve()`），
  沒有寫死任何絕對路徑，也不受 symlink／junction 影響。
- **設定從 `harness.config.json` 讀**：腳本自己會讀 `currentProject`，讀不到會拒跑並說缺什麼。
- **基準檔** 落在 `<harness>/SkillViewer/platform_skills.json`，第一次跑會自己建立基準
  （首次不報「新增一堆」，只建快照）。

⚠ **目前只支援 Claude Code 一種平台**。要監控別的 AI 工具（Cursor、Copilot…）
需要為那個工具寫一支取得技能清單的實作——**在有第二個實際要用的工具之前不預先抽象**
（`UNIVERSAL_HARNESS_PLAN.md` §5：為了通用而通用，抽象層本身不會讓任何人少犯錯）。

設計與三輪對抗式覆核紀錄見 `<harness>/SKILL_WATCH_PLAN.md`。
