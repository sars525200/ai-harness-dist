# 常駐層健檢與瘦身（/context-health）

> **這支存在的理由**：2026-08-13 實測 —— `check_bloat` 對 IT-dept MEMORY.md 報告
> 「88 條、**超標 0 條**」，同一天該檔尾段躺著 **6 段散文共 5,978 字**（最長一段 2,271 字）。
> 兩件事同時為真：那 6 段一條都不是「條目」，所以**偵測器完全看不見它們**。
> **盲區不會叫，它只是安靜。** 這支把「量 → 判 → 搬 → 驗」固定成一條走得完的路。

## 硬規則（違反的話就算數字變好看也算沒做）

1. 🔒 **禁止機械壓縮句子。** 刪錯的後果不是規則變短，是**規則失去觸發力**——模型
   認不出情境就永遠不會去開那份 topic 檔，等於規則消失。任何機械規則（刪括號、
   刪檔名、刪範例）都會系統性砍掉資訊密度最高的部分，因為那正好也是最長的部分。
   **允許的動作只有兩種**：①整塊搬到 on-demand 層，原位留一句帶症狀端觸發詞的索引
   ②合併同源條目（檔名列一次）。
2. 🔒 **MEMORY.md 禁止刪行。** 它本身就是索引，沒有更下層可搬。**刪掉一行＝那個
   topic 檔失聯**，而且沒有任何地方會報錯——只是模型再也不知道有那份檔。
   瘦它的手段只有「縮短 hook 句」與「合併同源條目」。
3. 🔒 **工具報的是「形狀」不是「對錯」。** 指路行、檔頭說明都可能合法地超過 120 字。
   **把「量到的形狀」講成「違規」會逼人去刪必要的導航**——那正是這條路最容易翻車的地方。
4. **搬移前必須確認目的地真的有那份內容。** 「我記得那邊有寫」不算；要 grep 到
   `檔:行`。2026-08-13 那次 6 段全數查證後才動手，唯一獨有的一句補進了 topic 檔。
5. **改完必須重跑量測並貼出前後數字。** 沒有前後對比的瘦身等於沒有交付。

## 步驟

### 1. 量現況（**兩支**唯讀工具，都不改檔；第三行是同一支的 JSON 輸出）

```
py -3 -X utf8 D:\.ai-harness\rulefile\check_bloat.py            # 條目層：>120 字的條目、快照比對、趨勢
py -3 -X utf8 D:\.ai-harness\rulefile\check_prose_blocks.py        # 結構層：散文塊、手抄清單、成本估算
py -3 -X utf8 D:\.ai-harness\rulefile\check_prose_blocks.py --json # 給後續步驟吃
```

**兩支要一起跑，因為它們的盲區互補**：`check_bloat` 只看得見 `- [` 索引列與 `|` 表格列；
`check_prose_blocks` 專看「不長成那樣」的東西。只跑其中一支會漏掉另一半，
而漏掉的症狀是「報告很乾淨」——跟「真的很乾淨」長得一模一樣。

`check_prose_blocks` 另外會給成本估算 = 字數 → token → $/月。
⚠ **是估算不是量測**（真量測在 `gen_cost_panel.py`），
而且省錢從來不是主要理由：**規則太多會找不到、讀不完。**

> ⚠ **「散文字數」只涵蓋一半**：條列、表格、條目的續行都歸 `check_bloat` 的條目層管。
> **把一段長散文改寫成條列，散文字數會大幅下降而內容一個字都沒搬**——
> 所以成效要看整份檔的**總量**（步驟 5 那一列），不能只看這裡的數字。

> ⚠ **P-9「手抄注入清單偵測」已於 2026-08-14 移除**。三版判準（絕對數→比例→
> 名字距離）全部被實測推翻，之後量過的兩個替代訊號也不成立——尤其
> **與 skill `description` 的字面重疊在真實資料上是反的**：真手抄抄的是*當時*的描述、
> 它已經漂了，而「會漂」正是要抓它的理由。**訊號與偵測目標互斥。**
> 「同一份資訊付兩次錢」這個問題仍然成立，但它**不是能用結構偵測的問題**——
> 判定它需要人讀兩邊。要重開這個能力，先讀 `CONTEXT_HEALTH_PLAN.md` §7 v12 的資料。

### 2. 對每個候選，先查它該去哪（不可跳過）

對每一塊候選，用 Grep 到 on-demand 層與 harness 計畫書找**它的完整版在不在別處**：

- 在 → 記下 `檔:行`，這塊可以壓成一句指路。
- 不在 → **這塊不能刪**。要嘛留著，要嘛先把它搬進某個 topic 檔再壓。
- 一部分在、一部分不在 → **最危險的一類**。2026-08-13 的實例：某段裡多數句子
  在 topic 檔有副本，但「零副本＝這顆磁碟壞掉全部歷史一起沒」這句風險判斷
  整個平台只有這一句。**逐句看，不要整段判。**

> ⚠ **不要期待自動化這一步。** 曾經做過一支跨檔重複偵測（`rulefile/find_duplicates.py`），
> 實測對那 6 段**0 命中**——它們是**摘要**不是副本，與來源連 75% 相似都不到。
> 「有更完整的版本」是語義關係，判定它需要人讀兩邊。那支工具留著（索引層是好的），
> 但**不要拿它的輸出當搬移依據**：它唯一穩定命中的是檔名引用與索引句，
> 而那些**本來就該重複出現**——照著搬會直接刪掉規則索引。

### 3. 逐項讓人決定

把候選整理成清單（位置｜字數｜內容摘要｜完整版在哪｜建議動作），
用**選擇題**問，不要用開放式問句。**沒有人點頭之前不動任何檔。**

### 4. 動手（照決定，不擴張範圍）

- 動 `.md` 前先確認行尾格式：`MEMORY.md` 常是 **CRLF**、`CLAUDE.md` 常是 **LF**。
  用 Python 改檔一定 `io.open(..., newline='')` 讀寫，否則產生巨量假 diff。
- 能用 Edit 就別用 Python（Edit 保留原行尾）。
- 搬走的內容若有一句是獨有的，**先補進目的地檔**再刪來源。

### 5. 驗證（缺一項都算沒做完）

| 驗什麼 | 怎麼驗 | 判準 |
|---|---|---|
| topic 檔沒失聯 | 瘦身前後各取一次 MEMORY.md 的索引檔名集合 | **必須完全相同**（差集非空即失敗） |
| 行尾沒被翻 | `git diff --stat` | 改幾行就顯示幾行；整檔重寫＝行尾被翻了 |
| 條目層沒退步 | 重跑 `check_bloat.py` | **exit 0 或 1 都算跑得起來**（1 是內容閘門不是故障）；條目數不得下降 |
| 結構層真的降了 | 重跑 `check_prose_blocks.py` | 散文字數下降，貼出前後數字 |
| 🔑 **總量真的降了**（不是換個形狀） | `check_bloat.py --history` 看 `visible` 趨勢 | **整份檔的可見字數必須下降**。⚠ 只看上面兩列會**對「純排版」說成功**：把一段散文改寫成 `- ` 條列，散文字數歸零、條目數上升，兩條判準同時綠燈**而一個字都沒搬**（實測 254 字的清單改條列 → prose 1 塊變 0 塊、bloat 0 條變 5 條 0 超標）。字沒搬走就是沒搬走，總量是唯一騙不了的那個數字 |

## 邊界（寫在這裡是因為不寫會被誤解）

- **這支只在被叫的時候跑。** `/shougong` 只存在於 IT-department，所以「每次收工自動量」
  只對那一個專案為真；其他專案是**手動叫這支**。裝了 harness ≠ 每個專案都會自己檢查。
- **不碰 `.claude/PROJECT_CONTEXT.md`。** 它不是 always-loaded（角色開工才讀），
  砍它的內容等於砍掉角色的作用對象設定，而那個失效沒有任何人會收到通知。
- **不改 harness 自己的計畫書**，只讀它們當作「內容的去處」。
- 判準、分岔與踩雷史在 `D:\.ai-harness\CONTEXT_HEALTH_PLAN.md`；
  這份 skill 只編排步驟，**規則本體不在這裡**。
- **量測結果寫 `D:\.ai-harness\CONTEXT_HEALTH_MEASUREMENTS.md`，不要寫進計畫書。**
  計畫書是 `> 狀態：待審核`、受 PR-1 覆核閘門管轄的檔——每量一次就改它一次，
  會讓「重算 hash」變成反射動作，而那正是偽造憑證的唯一動作
  （`hooks/rules/pr1_plan_review_marker.py` 檔頭 2026-07-29 第 4 點）。
  2026-08-26 實際踩過：append 一節量測紀錄就把 Stop 閘門觸發了。
