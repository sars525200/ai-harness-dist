# 常駐層健檢與瘦身（/context-health）

> **這支存在的理由**：偵測器有盲區，而**盲區不會叫，它只是安靜**——`check_bloat` 只看得見
> 索引列與表格列，檔尾躺著幾千字散文它照樣報「超標 0 條」（實測案例與判準演化見 `CONTEXT_HEALTH_PLAN.md`）。
> 這支把「量 → 判 → 搬 → 驗」固定成一條走得完的路。

## 硬規則（違反的話就算數字變好看也算沒做）

1. 🔒 **禁止機械壓縮句子。** 刪錯的後果不是規則變短，是**規則失去觸發力**——模型
   認不出情境就永遠不會去開那份 topic 檔，等於規則消失。任何機械規則（刪括號、
   刪檔名、刪範例）都會系統性砍掉資訊密度最高的部分，因為那正好也是最長的部分。
   **允許的動作只有兩種**：①整塊搬到 on-demand 層，原位留一句帶症狀端觸發詞的索引
   ②合併同源條目（檔名列一次）。
2. 🔒 **MEMORY.md 禁止刪行。** 它本身就是索引，沒有更下層可搬。**刪掉一行＝那個
   topic 檔失聯**，而且沒有任何地方會報錯——只是模型再也不知道有那份檔。
   瘦它的手段只有「縮短 hook 句」與「合併同源條目」。
   官方載入上限是 **200 行或 25KB，先到者**；超標會被安靜截斷。這是事實不是閘門，
   **不授權刪行**。
3. 🔒 **工具報的是「形狀」不是「對錯」。** 指路行、檔頭說明都可能合法地超過 120 字。
   **把「量到的形狀」講成「違規」會逼人去刪必要的導航**——那正是這條路最容易翻車的地方。
4. **搬移前必須確認目的地真的有那份內容。** 「我記得那邊有寫」不算；要 grep 到
   `檔:行`。2026-08-13 那次 6 段全數查證後才動手，唯一獨有的一句補進了 topic 檔。
5. **改完必須重跑量測並貼出前後數字。** 沒有前後對比的瘦身等於沒有交付。

## 步驟

### 1. 量現況（**兩支**唯讀工具，都不改檔；第三行是同一支的 JSON 輸出）

```
py -3 -X utf8 D:\Patrick-AI\.ai-harness\rulefile\check_bloat.py            # 條目層：>120 字的條目、快照比對、趨勢
py -3 -X utf8 D:\Patrick-AI\.ai-harness\rulefile\check_prose_blocks.py        # 結構層：散文塊、手抄清單、成本估算
py -3 -X utf8 D:\Patrick-AI\.ai-harness\rulefile\check_prose_blocks.py --json # 給後續步驟吃
```

**兩支要一起跑，因為它們的盲區互補**：`check_bloat` 只看得見 `- [` 索引列與 `|` 表格列；
`check_prose_blocks` 專看「不長成那樣」的東西。只跑其中一支會漏掉另一半，
而漏掉的症狀是「報告很乾淨」——跟「真的很乾淨」長得一模一樣。

`check_prose_blocks` 另外會給成本估算 = 字數 → token → $/月。
⚠ **是估算不是量測**（真量測在 `gen_cost_panel.py`），
而且省錢從來不是主要理由：**規則太多會找不到、讀不完。**

> ⚠ **「散文字數」只涵蓋一半**：條列、表格、條目的續行都歸 `check_bloat` 的條目層管，
> 所以成效要看整份檔的**總量**（步驟 5 的 🔑 那一列），不能只看這裡的數字。

> ⚠ **不要重做「手抄注入清單偵測」**（P-9，已移除）。三版判準與兩個替代訊號全部被實測推翻，
> 根因是**訊號與偵測目標互斥**：真手抄抄的是*當時*的描述、它已經漂了，而「會漂」正是要抓它的理由。
> 「同一份資訊付兩次錢」仍然成立，但**它不是能用結構偵測的問題**——判定它需要人讀兩邊。
> 要重開先讀 `CONTEXT_HEALTH_PLAN.md` §7 v12。

### 2. 對每個候選，先查它該去哪（不可跳過）

對每一塊候選，用 Grep 到 on-demand 層與 harness 計畫書找**它的完整版在不在別處**：

- 在 → 記下 `檔:行`，這塊可以壓成一句指路。
- 不在 → **這塊不能刪**。要嘛留著，要嘛先把它搬進某個 topic 檔再壓。
- 一部分在、一部分不在 → **最危險的一類**。實例：某段多數句子在 topic 檔都有副本，
  但其中一句風險判斷整個平台只有那一句。**逐句看，不要整段判。**

> ⚠ **不要期待自動化這一步。** 跨檔重複偵測（`rulefile/find_duplicates.py`）對這類候選
> 實測 **0 命中**——它們是**摘要**不是副本。「有更完整的版本」是語義關係，需要人讀兩邊。
> 那支工具留著（索引層是好的），但**不得拿它的輸出當搬移依據**：它唯一穩定命中的是
> 檔名引用與索引句，而那些**本來就該重複出現**——照著搬會直接刪掉規則索引。

> ⚠ **自己寫的關鍵詞比對會系統性低估覆蓋率，而那個方向的錯最貴。**
> 2026-08-28 一天內連中**五次**：關鍵詞說「13 條裡只有 5 條目的地有」，逐條讀完是 **9 條**；
> 說「這兩列零命中」，實際「停舊→起新→驗證」一字不差就在目的地。
> 根因是**目的地通常寫得比常駐層更詳細**，用的詞因此不一樣——常駐層寫結論，
> 目的地寫根因與現場，關鍵詞自然對不上。
>
> **為什麼低估比高估貴**：低估 ⇒ 你會「保守地留著」，那只是沒省到；
> 但你也可能因此**判定「這條沒有副本」而去補一份到目的地**，於是同一件事變成兩份、
> 之後各自漂移。高估則是直接刪掉唯一副本——那個更嚴重，但**人讀兩邊就不會發生**。
> ⇒ 機械比對只准拿來**縮小要人讀的範圍**，不准拿來下「有／沒有」的判定。

### 2.5 決定它該去哪一層（四層決策樹·2026-08-26 兩輪對抗式覆核後訂）

依序問，第一個「是」就落在那一層：

| 層 | 問題 | 常駐成本 | 觸發可靠度 | 官方對應 |
|---|---|---|---|---|
| **hook／閘門** | 能不能機械檢查？（觸發時機確定 ＋ 錯誤形狀可判定 ＋ 替代路徑明確） | 0 | 最高，零「認不認得」 | 能 hook／linter 強制的不進 CLAUDE.md |
| **窄 path-scoped** | **犯錯那一刻，哪個檔已經在 context？** | 0（碰到才載） | 高，但要過下面三個測試 | path-scoped 才真減肥（`@import` 不能） |
| **併進既有 skill** | 症狀對得上某支**既有** skill 的 description 嗎？ | 0（不新增 description） | 中，押在 model-invoked | 流程／領域進 skill（三層 disclosure） |
| **留常駐** | 以上皆否 | 全額 | 最高但最貴 | 拿掉會犯錯才留（`/doctor`） |

⚠ **判準是「犯錯當下哪個檔在 context」，不是「規則內文提到哪個檔」。**
後者是成本貪婪——規則一出現檔名就想塞進 path-scoped，那會做出一批綁了也不會載入的規則。

**path-scoped 的三個否決測試（任一命中就不可）**

1. **反綁**——若「已經打開那個檔」本身就代表你沒犯這個錯，那是反綁。
   典型：「清理刪檔時要記得涵蓋某個被忽略的目錄」綁那個目錄。
2. **動作**——觸發時機是動作（部署、推送、批次替換、清理、遠端複製），
   path-scoped 靠檔案存取觸發，動作不碰檔就不會載。
3. **寬度**——glob 覆蓋專案主路徑 ⇒ 實質準常駐，省不到 token，只換來「已經搬走了」的錯覺。

**兩個容易算錯的成本**

- **「搬到全域」是最貴的層**（所有專案 × 所有對話），不是省。實測搬 3 條規則到全域，
  單一專案的對話總量反而 **+770 bytes**。分層正確與省 token 會衝突，先承認再取捨。
- **「併進既有規則檔＝零成本」只在該檔本來就不常載入時成立。** 若那支規則檔的 glob
  命中專案主路徑，併進去只是把成本從「100% 的對話」降到「那類任務的對話」，不是消失。
  實測一支規則檔 4,375 bytes ≈ 1.1k tokens，**單次載入就可能超過整輪瘦身省下的量**。

**指向 skill ≠ 指向規則檔／記憶檔（這一條最容易漏）**

常駐層的索引句若指向 `/xxx` **skill**，那支 skill 的 description 也是常駐的
⇒ 兩邊重複時可以刪索引句。但若指向的是 **path-scoped 規則檔或記憶檔**，
**那些東西沒有常駐 description** ⇒ 索引句是它們**唯一的常駐入口**，刪掉不是搬家、是斷線。
**動索引句前先確認目標有沒有 description。**

**第四種處置：索引化**

一整塊「查表型」內容（模組清單、文件對照表）若每一項都指向不同的檔，
往往三層都不適合：綁 path-scoped 會落在同幾個熱檔（寬度測試不過）、
併進 skill 沒有對應的那一支。這時把整塊搬進一份 `INDEX.md`、常駐層只留**一行指標**，
效益常常遠大於在條目裡摳字。實測：13 行換一行，省下的是整輪其他工作的四倍。

### 3. 逐項讓人決定

把候選整理成清單（位置｜字數｜內容摘要｜完整版在哪｜建議動作），
用**選擇題**問，不要用開放式問句。**沒有人點頭之前不動任何檔。**

### 4. 動手（照決定，不擴張範圍）

- **動之前先看檔頭有沒有 `<!-- GENERATED FILE -->`。** 有 → 那份是產出檔，改它會被下次
  產生器重生蓋掉；去改它指名的源頭（例如 `global/hub/*.md`），改完跑對應產生器
  （例如 `py -3 tools/gen_rule_hub.py`）重生，再部署到 live 路徑。專案自己的
  `CLAUDE.md`／`MEMORY.md` 說法可能沒跟上（2026-09-03 實測：harness 自己的 CLAUDE.md
  說「產生器上線前過渡仍改 global/CLAUDE.md」，但那份檔案當時已經是產出檔）——**檔頭的
  標記比專案說明文件準，兩者矛盾時信檔頭**。
- 動 `.md` 前先確認行尾格式：`MEMORY.md` 常是 **CRLF**、`CLAUDE.md` 常是 **LF**。
  用 Python 改檔一定 `io.open(..., newline='')` 讀寫，否則產生巨量假 diff。
- 能用 Edit 就別用 Python（Edit 保留原行尾）。
- 搬走的內容若有一句是獨有的，**先補進目的地檔**再刪來源。

### 5. 驗證（缺一項都算沒做完）

人點頭「本次量測作實」之後、看趨勢之前，先寫一筆（步驟 1 仍唯讀、此時才寫）：

```
py -3 -X utf8 D:\Patrick-AI\.ai-harness\rulefile\check_bloat.py --append-history
```

沒點頭＝不寫。沒寫＝沒有真實量測＝下面 🔑 列紅。
`--write-snapshot --project <名稱>` 只有人明示「接受現況當新基準」才跑，不是這一步的預設。

| 驗什麼 | 怎麼驗 | 判準 |
|---|---|---|
| topic 檔沒失聯 | 瘦身前後各取一次 MEMORY.md 的索引檔名集合 | **必須完全相同**（差集非空即失敗） |
| 行尾沒被翻 | `git diff --stat` | 改幾行就顯示幾行；整檔重寫＝行尾被翻了 |
| 條目層沒退步 | 重跑 `check_bloat.py` | **exit 0 或 1 都算跑得起來**（1 是內容閘門不是故障）；條目數不得下降 |
| 結構層真的降了 | 重跑 `check_prose_blocks.py` | 散文字數下降，貼出前後數字 |
| 🔑 **總量真的降了**（不是換個形狀） | `check_bloat.py --history` 看 `visible` 趨勢 | **整份檔的可見字數必須下降**。少於兩筆**真實量測**仍宣稱趨勢成立＝紅（合成列／單筆不算）。`--history` 的 **exit 0 只代表「至少有一條線 ≥2 筆」**，不是本次動的那一檔已經能比——該檔那一列若仍是「基準／只有一筆」＝本列紅。工具 exit 0 且印「比不出趨勢」不能當這列綠。⚠ 只看上面兩列會**對「純排版」說成功**：把一段散文改寫成 `- ` 條列，散文字數歸零、條目數上升，兩條判準同時綠燈**而一個字都沒搬**（實測 254 字的清單改條列 → prose 1 塊變 0 塊、bloat 0 條變 5 條 0 超標）。字沒搬走就是沒搬走，總量是唯一騙不了的那個數字 |

## 邊界（寫在這裡是因為不寫會被誤解）

- **這支只在被叫的時候跑。全程手動，含 IT。** `/shougong` 不做健檢（2026-08-23）。
  裝了 harness ≠ 每個專案都會自己檢查。
- **不碰 `.claude/PROJECT_CONTEXT.md`。** 它不是 always-loaded（角色開工才讀），
  砍它的內容等於砍掉角色的作用對象設定，而那個失效沒有任何人會收到通知。
- **不改 harness 自己的計畫書**，只讀它們當作「內容的去處」。
- 判準、分岔與踩雷史在 `D:\Patrick-AI\.ai-harness\CONTEXT_HEALTH_PLAN.md`；
  這份 skill 只編排步驟，**規則本體不在這裡**。
- **量測結果寫 `CONTEXT_HEALTH_MEASUREMENTS.md`（`<harness>\CONTEXT_HEALTH_MEASUREMENTS.md`），不要寫進計畫書。**
  計畫書受 PR-1 覆核閘門管轄，每量一次就改它一次會讓「重算 hash」變成反射動作，
