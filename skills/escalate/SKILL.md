# 請示（escalate）

漏的不是「角色會不會喊」，是收到之後有沒有落檔、有沒有把決定權還給人。
數字與設計見 `HARNESS_ROLE_ARCH_PLAN.md` §9。閘門 `ESC-1` 只看得到「角色喊了」，看不到落檔——這支管那一半。

## 步驟

### 1. 先確認這是不是「不得默默繞過去」的情境

命中任何一條就往下走：

- 角色回報裡出現 `【需要但沒有】`／`【受阻】`
- 你自己在同一條路徑上重試而不會通（同一個錯反覆出現）
- 你正打算做一件**規格沒要求、但不做就過不去**的事
- 你心裡冒出「算了我繞過去」——**這一句本身就是觸發條件**

**門檻不因為「是我自己在做」而放寬**：上面後三條就是給主 session 的，自己踩到照樣走完步驟 2–5。

**完成判準**：講出是哪一條命中了，且沒有用「這次是我自己」當豁免。都沒命中就不必用這支。

### 2. 不得默默繞過去——**自己想得出繞法也不行**

**「我知道怎麼繞」不是跳過請示的理由**，繞法要當成選項之一講出來，由人選。
繞路成功不會留下痕跡——做不到會喊，繞過去了不會喊。

**完成判準**：回覆裡出現了「繞法」這個選項，而不是直接執行它。

### 3. 判規模，決定要不要寫計畫書

沿用**全域** `CLAUDE.md` §3 工作流的 L／S／M 分級（不另立一套；專案那份的 §3 不是這個）：

- **M 級** → 寫計畫書。**若本專案有 Design 階段執行器就走它**；沒有就寫五節：現況 → 目標 → 做法 → 驗證 → 狀態。
- **其餘** → 不寫計畫書，直接進步驟 4。

⚠ **不要硬編別的專案不一定有的 skill 名字**。全域層指向空氣不會報錯。

**完成判準**：級別已講出來；M 級的話計畫書落點也講出來。

### 4. 帶回去的東西**四件齊全**

| 要件 | 判準 |
|---|---|
| **卡在哪** | 一句話說得完，且是**具體的那一步** |
| **已試過什麼** | 每項一行。**沒試過就不要列** |
| **選項＋各自的成本估計** | **至少兩個**，含「繞過去」與「不做」。成本要有量級 |
| **我的傾向與理由** | 有傾向就講。**沒有傾向就寫「無」** |

**用選擇題問。**「兩件事留給你決定：…」句號結尾正是 `AWC-1` 在擋的形狀。

**完成判準**：四欄都有內容，且問句是選擇題形態。

### 5. 落檔——這一步是整條鏈唯一會漏的地方

屬於「需要但沒有」的，抄進 `TODOS.md` 的「全域·需求」表（**不新建表**）。
角色多半沒有 Write 權限，**落檔一定是主 session 的責任**。

兩種都收：①做不到 ②做得到但明顯繞路多花時間。②必須附這次實際發生的實例。

**完成判準**：`TODOS.md` 的列數增加了，或說得出為什麼這一筆不屬於那張表。

## 邊界

- **不替人決定。** 選項與成本擺出來之後就停。
- **不改任何檔、不改設定、不部署。**
- **不判斷需求合不合理。** 登記是登記。
- 可重現的 code bug、無法重現的資料事故：部門專案若有對應 skill 才走；沒有就留在這支請示裡。
- 規格沒寫清楚 → 回去補規格，那不是受阻。
- 收到 ESC-1 的 WARN 之後走這支，不是「已經有閘門了就不用管」。

## 交出什麼

一則請示：**卡在哪／已試過什麼／選項＋成本／我的傾向**，用選擇題收尾。
加上（若適用）`TODOS.md` 多出來的那一列，或計畫書的落點。
下一棒不必回頭問你任何事就能做決定。
