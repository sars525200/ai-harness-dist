# 請示（escalate）

> **這支 skill 存在的理由是一組實測數字**：303 份角色回報裡有 **37 筆真需求**被喊出來，
> 而 `TODOS.md`「全域·需求」表只有 **3 列**。角色端一直在運作，
> **漏的是收到之後的那一步**——而漏掉的方式幾乎都是「我自己繞過去了，沒人知道」。
>
> 執行期閘門是 `ESC-1`（`Stop` 事件·enforce）。它只看得到「角色喊了」，
> 看不到「有沒有落檔」——所以這支 skill 管的是它看不到的那一半。

## 步驟

### 1. 先確認這是不是「不得默默繞過去」的情境

命中任何一條就往下走：

- 角色回報裡出現 `【需要但沒有】`／`【受阻】`／`【成本超標】`
- 你自己在同一條路徑上重試而不會通（不是換方法，是同一個錯反覆出現）
- 你正打算做一件**規格沒要求、但不做就過不去**的事
- 你心裡冒出「算了我繞過去」——**這一句本身就是觸發條件**

**完成判準**：講出是哪一條命中了。都沒命中就不必用這支。

### 2. 不得默默繞過去——**自己想得出繞法也不行**

這是整支 skill 的核心，而且它反直覺：**「我知道怎麼繞」不是跳過請示的理由，
繞法要當成選項之一講出來，由人選。**

現況的失效模式不是「不知道怎麼辦」，是「**自己解決掉了、沒人知道**」。
繞路成功不會留下任何痕跡——做不到會喊，繞過去了不會喊，
而不喊的那些正是配置永遠不會被修正的原因。

**完成判準**：你的回覆裡出現了「繞法」這個選項，而不是直接執行它。

### 3. 判規模，決定要不要寫計畫書

沿用 `CLAUDE.md` §3 的分級（不另立一套）：

- **M 級**（資料遷移／DELETE・動角色·規則·hook・跨 repo・預估跨 session）
  → 寫計畫書。**若本專案有 Design 階段執行器就走它**（本專案是 `/design-spec`）；
  沒有就直接寫五節：現況 → 目標 → 做法 → 驗證 → 狀態。
- **其餘** → 不寫計畫書，直接進步驟 4。

⚠ **不要硬編別的專案不一定有的 skill 名字**。這支是全域層，
指向一個只存在於某個專案的 skill＝換部門就是指向空氣，而且不會報錯。

**完成判準**：級別已講出來；M 級的話計畫書落點也講出來。

### 4. 帶回去的東西**四件齊全**

缺任何一件，對方就沒辦法判斷，於是這次請示會退化成「你自己看著辦」：

| 要件 | 判準 |
|---|---|
| **卡在哪** | 一句話說得完，且是**具體的那一步**，不是「這個功能有問題」 |
| **已試過什麼** | 每項一行。**沒試過就不要列**——列了會讓對方以為那條路已經排除 |
| **選項＋各自的成本估計** | **至少兩個**，含「繞過去」與「不做」。成本要有量級（幾檔／幾輪／要不要重啟） |
| **我的傾向與理由** | 有傾向就講，理由要能被反駁。**沒有傾向就寫「無」**——那也是一個判定 |

**用選擇題問，不要用陳述句把決定丟回去**。「兩件事留給你決定：…」句號結尾
正是 `AWC-1` 在擋的形狀。

**完成判準**：四欄都有內容，且問句是選擇題形態。

### 5. 落檔——這一步是整條鏈唯一會漏的地方

屬於「需要但沒有」的，抄進 `TODOS.md` 的「全域·需求」表（**不新建表**）。
角色多半沒有 Write 權限（`locator` 只有 Read/Grep/Glob），
**落檔一定是主 session 的責任**——這條漏掉的話整個機制等於沒有。

兩種都收：①**做不到**（被工具限制擋住）②**做得到但明顯繞路多花時間**。
②必須附**這次實際發生的實例**，沒有實例的不要登記，那是想像中的需求。

**完成判準**：`TODOS.md` 的列數增加了，或說得出為什麼這一筆不屬於那張表。

### 6. 主 session 自己撞到時同樣適用

門檻不因為「是我自己在做」而放寬。你繞過去的那一次同樣不會留下痕跡，
而且比角色繞過去更難發現——沒有回報可以事後翻。

**完成判準**：自己踩到時也走了步驟 2–5，而不是「我這次就先繞一下」。

## 邊界

**這支不做的事**（做了就是越權，或走錯支）：

- **不替人決定要不要做那件事。** 它唯一保證的是決定權回到人手上——
  把選項與成本擺出來之後就停，不要順手挑一個開始做。
- **不改任何檔、不改設定、不部署。** 請示是把情況講清楚，不是動手。
- **不判斷需求合不合理。** 登記是登記；「值不值得做」是 `TODOS.md`
  那張表的擁有者之後要判的，提出者判它等於替人做決定。

**什麼情況改走別支**：

- 可重現的 code bug → `/diagnose-bug`。那是「查根因」不是「卡住要喊」。
- 已經發生、無法重現的資料事故 → `/data-incident`。
- 純粹是規格沒寫清楚 → 回去把規格補完，那不是受阻，是規格缺口。

**與 `ESC-1` 的分工**：`ESC-1` 是執行期閘門，看得到「角色喊了」、
**看不到「有沒有落檔」**。這支管的正是它看不到的那一半——
所以收到 ESC-1 的 WARN 之後走這支，不是「已經有閘門了就不用管」。

## 交出什麼

一則請示：**卡在哪／已試過什麼／選項＋成本／我的傾向**，用選擇題收尾。
加上（若適用）`TODOS.md` 多出來的那一列，或計畫書的落點。

下一棒（人）要能**不必回頭問你任何事**就做出決定——那是這支 skill 唯一的成功判準。
