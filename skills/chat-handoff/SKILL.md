# 換則交接（/chat-handoff）

把**這則對話裡還沒進記憶／計畫書的臨時脈絡**寫成檔，讓下一則空對話接得上。

## 為什麼改成邊做邊寫（2026-09-03 實測後定）

撈了六則「貼交接檔開場白」的接手對話。飄離主線的機制不是跑去做別的事，是
**接手方不敢相信交接檔，先全面重新核對**，而核對過程長出支線 —— 某則第一輪
20 多個查證動作，產出是「交接檔又有一處過時」與「順手驗了三個技術主張」，
三件都不在主線上。而它的不信任是對的：同一則真的抓到兩處對不上。

事後回憶寫出來的檔必然過時。**寫入時機從「換則前」移到「當下」是解方；
補背景不是** —— 補背景只會讓檔更長，而長度本身是新的過時來源。

## 邊界

- `/clear` 只能由 user 執行；本 skill 只落檔並給出可貼的第一句。
- 「收工／先到這／封存」若指補規範、待驗或多 repo commit，改用部門專案的
  `/shougong`（若有）。
- 任務檔是 session 暫存。不得以版控內的 `HANDOFF.md`／`*_PLAN.md` 代替，也不為交接
  建 branch 或 commit。
- 本支定**檔長什麼樣**；**什麼時候追寫**在 `/session-workflow` 各步驟的完成判準。
  兩支不重複寫同一件事。

## 0. 開工就建（S／M 級）

自我宣告寫完就建檔，不必等人開口，也不必等對話變長。**L 級不建**（單點工作，
建了只是垃圾）。

**用 `tools/new_handoff.py` 建，不要手打**（2026-09-06 起）：

```
py -3 tools/new_handoff.py --task "<任務名>" --type task
py -3 tools/new_handoff.py --task "<任務名>" --type research \
    --plan <計畫書路徑> --sections "§4, §7"
```

`--type` 二選一見下節「兩套骨架」。有主計畫書就帶 `--plan`／`--sections`——
這是這則交接要「把主任務的計畫書一起帶給下一個接手窗口」的地方，寫在
frontmatter 不是散文裡，下一棒才找得到。落在 `.scratch/handoff/YYYYMMDD-<slug>.md`
（目錄沒有就建）。不建 git 分支、不 commit。

工具會把五欄 frontmatter 一次寫齊；`hooks/rules/hnd2_frontmatter_contract.py`（HND-2）
會在**每次存檔**檢查這五欄，缺了就擋。開工當下只填「目標」「硬限制」兩段，
其餘留空等追寫。

## 1. Frontmatter 契約（兩套骨架共用，HND-2 強制）

```
---
status: open              # open | done | closed | archived | superseded
type: task                # task | research —— 決定正文用哪套骨架
task: <任務名>              # 跟自我宣告「任務」欄同一個名字
plan: 無                   # 主計畫書相對路徑，例如 TOKEN_COST_PLAN.md；沒有就「無」
plan_sections: 無          # 要讀哪幾節，例如 "§4, §7"；plan 是「無」時這裡也要是「無」
---
```

**這一段不是裝飾，是可查證的事實**：`status` 讓 HND-1／`archive_handoff.py`
判斷哪些還開著；`plan`／`plan_sections` 讓下一棒不必翻散文就知道主計畫書在哪、
該讀哪幾節。事情做完把 `status` 改成 `done`。**留空＝永遠開著**——HND-2 從
2026-09-06 起會在存檔當下擋下不合格的 frontmatter，不必再靠自覺記得補。

## 2. 兩套骨架——依任務形狀選，不是都用同一套

**`--type task`**（分階段推進的工作，例如遷移、修規則、跨檔改動）：

```
## 目標               ← 開工寫，之後不改；改了就是轉向，見下
## 硬限制             ← 不要做的
## 進度日誌           ← 階段轉換時往下追加，不回頭改
## 未完成／等人點頭    ← 換則時才整理
## 新對話建議第一句    ← 換則時才寫
```

**`--type research`**（量測、調查、單輪產出——硬套七段會逼出空的「進度日誌」）：

```
## 一句話現況
## 關鍵數字（接手不必重算）
## 已改的東西
## 沒做的（刻意，不是漏掉）
## 待驗清單（四欄齊全，空白＝沒驗過）
## 基準線（下次對照用這組）
## 新對話建議第一句
```

正文結構 HND-2 不驗——判準綁章節名字換個寫法就繞過去，這是 EXP-1／HND-1
都踩過的坑。選錯型別、正文寫得七零八落，是人與下一棒自己要面對的事。

### 進度日誌怎麼寫（`--type task` 專屬）

每次階段轉換追加一段，**上限 5 行**。超過就是把過程當交付物在寫。

```
### [Research] <任務名>
- 做了什麼：一行
- 為什麼是這個決定：一行（沒有決定就寫「無」）
- 沒做的：一行
```

- **只追加，不回頭改**。前面寫錯了就在新的一段寫「上一段的 X 已作廢，因為…」。
  原文留著，當初的判斷過程才查得到。
- **段落標題帶任務名**。轉向時這裡會先長出兩個不同的名字 —— 那是失焦最早的訊號，
  比事後回想準。
- 細節已在 `CLAUDE.md`、`*_PLAN.md` 的，寫「見某某檔」，不要把規則本文再抄一次。

## 3. 換則時做什麼

**不重新回憶**。日誌已經在檔裡了，只做三件：

1. 檔頭補一行「本則到此為止」的一句話狀態
2. 整理「未完成／等人點頭」—— **主線只留一件**，其餘標「本則不做」
3. 寫「新對話建議第一句」，指向這份檔

清除方式：Claude Code `/clear`（進行中變長先 `/compact`）；Cursor 輸入框打 `/clear`
（`/new` 相同），只想壓短就 `/summarize`。

回覆最後一行放檔案路徑，以及「請你打 `/clear` 後把上面那句貼進新對話」。

## 4. 結案（事情做完之後回來做的）

- 把 `status: open` 改成 `done`，並在檔頭加一段逐條狀態（哪個問題修在哪顆 commit）
- **檢查它的指路還成不成立**：搬過家的函式、已作廢的「新對話建議第一句」。
  原文不要刪 —— 只加狀態、劃掉作廢的段落。

搬進歸檔區用 `py -3 tools/archive_handoff.py`（不加旗標只印計畫，`--move` 才真搬；
只搬已標結案的，不刪檔）。

**完成判準**：磁碟上有那份 md、帶著 `status` 欄；S／M 級的進度日誌段數 ≥ 走過的階段數；
人不必翻這則歷史就能在新對話開工。
